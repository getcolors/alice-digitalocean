alice-digitalocean

One short-lived DigitalOcean Droplet running Transmission. The RPC web UI listens on loopback and is reached through SSH.

Health criterion: create succeeds only after curling the Transmission UI through a real SSH local forward.

Operate

./green validate
./green build
./green create --dry-run
./green create
./green sync
./green describe
./green tunnel 19091

Open http://127.0.0.1:19091/transmission/web/ while the tunnel command runs. Sync prints the same URL, downloads both desired Kali images, copies them directly into ~/Downloads/alice, and destroys the Droplet only after its final checksummed rsync succeeds.

Credentials and safety

The DigitalOcean token exists only as COLORS_PAR_DO_TOKEN in ignored .envrc.private. Never set COLORS_PAR_PROFILE, edit generated .colors/, or commit either location. SSH is the RPC authentication boundary; the Ubuntu 24.04 Transmission AppArmor profile is disabled because its systemd notify access fails even in complain mode.

Destroy guard: keep compute-prevent-destroy: true. COLORS_PAR_COMPUTE_PREVENT_DESTROY is ignored; explicit delete authorizes manual destruction, while sync authorizes only successful post-rsync cleanup.

Recovery

Rerun create to converge an intact Droplet. For service failures, use the SSH alias and inspect systemctl status transmission-daemon and journalctl -u transmission-daemon. Local OpenTofu state is required for deletion; if it is lost, recover or import the Droplet before proceeding.
